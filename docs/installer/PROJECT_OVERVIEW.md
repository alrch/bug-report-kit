# Общий установщик Bug Report Kit

Установщик даёт оператору повторяемый способ зарегистрировать или установить,
обновить, проверить и восстановить серверный экземпляр Bug Report Kit.
Отчёты, снимки, вложения, доступы и приватный config отделены от сменяемого кода.
Результат — проверенная работающая версия либо явное состояние восстановления.
Эта справка относится к мини-проекту установщика, не ко всем функциям Kit.

Владелец выбирает артефакт и разрешает поставку. Оператор передаёт приватные
параметры и запускает команду. Owning-приложение предоставляет адаптер своих
Compose, прокси и общего замка. Тестировщики пользуются прежними виджетом и
панелью; установщик не обрабатывает карточки и не принимает исправления.

Пример: оператор планирует обновление текстового сервера, затем применяет его.
Исполнитель сохраняет приватный backup, запускает кандидата и фактическую
предыдущую версию на одной временной копии, проверяет данные и готовность,
меняет только свою службу. При неудачной внешней проверке возвращает прежний
код на текущих данных. После прерывания другой запуск восстанавливает операцию
по журналу. [Руководство](PRODUCT_GUIDE.md) разбирает этот путь и исправление.

Стек: общий Python 3 bootstrap, прежние Node.js 24+ CLI/runtime, Docker CLI, неизменяемые локальные ID
образов или digest-ссылки, online backup SQLite и supervisor Kit. Отдельного
веб-сервера установщика нет. [Технический паспорт](PASSPORT.md) объясняет схему,
транзакцию и границу Docker. В JSON — ссылки вместо значений секретов; config
и данные принадлежат проекту. Приватные backup и журналы не используются для
автоматического отката БД.

Поддержан текстовый Docker-сервер с заранее подготовленными образом и хранилищем.
Общий драйвер владеет отдельным маркированным контейнером. Для существующего
Compose нужен явный доверенный адаптер приложения. Общая Compose-логика находится
в Kit; проектный модуль задаёт ресурсы и использует прежний замок поставки. Нативный macOS, голос,
получение и сборка образов, хранение offsite-копий и расписания за границей
этого этапа. Прежние сервисные API остаются доступными.
