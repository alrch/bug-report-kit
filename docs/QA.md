# Проверка перед приёмкой

Проверки ниже выполняются на временных локальных HTTP-серверах и отдельной SQLite-базе. Они не создают тикеты в рабочем проекте и не меняют статусы реальных багов.

```sh
npm ci
npm test
npx playwright install chromium
npm run test:browser
```

`npm test` проверяет сервер: авторизацию по проекту и роли, переходы статусов и ревизии, фильтрацию до пагинации, HTML и сводки, миграцию старой базы, резервную копию. `npm run test:browser` собирает виджет и проверяет его в настоящем Chromium:

| Риск из истории разработки | Проверка |
| --- | --- |
| Неверный снимок после прокрутки, обратного выделения или при сломанной картинке | Центр снимка сверяется по цвету с выбранной областью; сохраняются координаты и изображение |
| SVG-значок превращается в пустой квадрат (случай шапочки на странице выбора роли LMS) | После выделения локального SVG в превью проверяются пиксели его цвета; режим снимка сопоставлен с реальной страницей LMS |
| Смещение при масштабе 200% и перекрытие действий страницы кнопкой | Сверка пикселей, отмена малого выделения и размещение кнопки возле фиксированного элемента |
| Прерывание касания прокруткой браузера | Настоящий touch-жест открывает форму и завершает выделение |
| Сбой canvas и потеря изображения | Скрыто пустое превью; отдельный файл принят сервером, а снимок остался отсутствующим |
| Файл подменяет снимок или отвергается по расширению | Произвольный документ сохраняется рядом со снимком без изменения его пикселей; лимит одного файла — 5 МБ |
| Ошибка отправки и потеря текста | После HTTP 503 и после обрыва сети поля сохраняются, повторная отправка проходит |
| Секреты в URL и диагностике | Неизвестные query-параметры отсекаются; единственный UUID project_id сохраняется клиентом и сервером; сетевое событие не содержит токен |
| Несколько авторов и смена сессии | Форма берёт текущие имя, контакт и ID при открытии; тикет хранит эти поля. Гостевой ID сохраняется после перезагрузки и отличается в новом профиле браузера. Отдельный auth-проект проверяет регистрацию с четырёхзначным PIN, проверку сохранённой сессии, повторный вход и передачу серверного токена без доверия к полям автора клиента |
| Очередь перегружена или скрывает результат исправления | Панель показывает суть, статус, снимок и файл; пустые технические поля скрыты. После передачи исправления показывает итог и требует комментарий проверяющего при приёмке. История, технические сведения и отчёт за период доступны отдельно |

Дополнительно 15.10.2026 выполнена точечная проверка API в отдельной базе: ограничения ролей и проектов, конфликты ревизий, самоссылки и цепочки группировки, чужие и некорректные URL, поддельные и слишком большие снимки, лимит запроса, некорректные периоды, 205 записей с фильтрацией и пагинацией. Все семь групп прошли. Это проверка логических границ сервера; браузерный набор выше закрепляет видимые регрессии.

Для принимающего на конкретном подключённом проекте:

1. Открыть страницу каждого разрешённого контура на настольном и мобильном браузере, проверить положение кнопки и выделение области.
2. Отправить один тестовый тикет, сверить адрес, контур, версию приложения, описание, координаты, снимок и диагностику в панели.
3. Открыть HTML-отчёт и сводку за этот день. Проверить, что в очереди нет пустых полей, а после исправления видны резюме, имя проверяющего и запись истории.
4. На странице с личными данными осмотреть снимок до отправки. Приложить пробный файл любого формата и проверить, что он сохраняется отдельно от снимка; при невозможности автоснимка отправить тикет без снимка.
5. Убедиться, что конкретная CSP, HTTPS-прокси, разрешённый origin и рабочий браузер пропускают загрузку скрипта, CSS и POST. Локальные автоматические проверки не подтверждают инфраструктуру чужого контура.

Для LMS локальное сравнение встроенной формы и Kit выполнялось на Web и Admin `/login`, а также на Landing `/`. Kit создал тикеты со снимком из всех трёх приложений; сенсорный жест проверен в Admin, URL с query-параметром — в Web. Встроенная ссылка Landing передала очищенный адрес в Web. LMS API во время сравнения не был запущен, поэтому встроенная отправка Web/Admin проверялась перехватом запроса. Защищённые LMS-страницы и удалённые контуры требуют отдельной проверки при их доступности.
