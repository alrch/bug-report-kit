# Панели Kit за общим входом

Функция: участник открывает проектную панель после входа в доверенный портал;
несколько проектных панелей могут использовать один экземпляр Kit. При этом
прежний корневой вход по PIN остаётся доступен, если включён существующей
конфигурацией проекта. Старый одиночный `panelGateway` продолжает работать.

Для каждого пути `panelGateways[]` задаёт собственные `mountPath`, `signInPath`
и `logoutPath`; `preserveLegacy` обязателен и равен `true`. Пути относительны
к тому же origin, непустой префикс заканчивается `/`, совпадающие и вложенные
префиксы отклоняются до запуска. Конфигурация одного и нескольких шлюзов
одновременно запрещена. Корневой `/` и прежний `/dashboard.js` продолжают
обслуживать обычную панель; каждая панель Hub получает HTML и скрипт на своём
префиксе. Префиксы не могут пересекаться с `/api/` или `/reports/`, а вход и
выход — вести внутрь того же префикса. Ошибочная конфигурация не должна создавать
базу или запускать сервис.

Сама разметка не аутентифицирует пользователя и не ограничивает доступ к данным.
Внешний доверенный шлюз обязан проверять каждую сессию, не пропускать входящую
подделанную идентичность и использовать для каждой панели отдельный серверный
токен со scope соответствующего проекта. Прямой API продолжает проверять
токены и изоляцию проектов. Список `panelAccountIds` отдельно сохраняет
разрешённые старые PIN-аккаунты; новые отправители не получают доступ к панели
автоматически. Значения токенов и приватные конфигурации не входят в Git.

Связанные сценарии: [проверки нескольких панелей](../tests/panel-multigateway.test.mjs),
[совместимость одного шлюза и PIN](../tests/panel-compat.test.mjs),
[развёртывание и миграция](DEPLOY.md#панель-за-шлюзом-с-общей-сессией).
Последние проверки и рабочий выпуск — отдельные факты; включение кода в Git
не доказывает поставку или настройку Nginx.
