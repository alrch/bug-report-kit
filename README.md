# Bug Report Kit

**Embeddable, self-hosted bug reporting for web apps with screenshots, a shared team inbox, and an agent-ready API.**

**`bug-report-kit`** — самостоятельный сервис для веб-проектов. Тестировщик выделяет область страницы и описывает проблему. Команда видит читаемый тикет, разработчик или агент фиксирует причину, код и проверки, а проверяющий принимает результат. Контур определяется по адресу страницы: `localhost` — `local`, остальные — имя домена. Подробный контракт: [docs/WORKFLOW.md](docs/WORKFLOW.md).

## Быстрый запуск

Требуется Node.js 24+.

```bash
npm install
npm run build
cp config.example.json config.local.json
```

Замените в `config.local.json` все примеры ключей на случайные значения. Публичный `widgetKey` можно включить в страницу. Приватные `teamTokens[].token` предназначены только команде; в код приложения их не добавляют. Укажите адреса сайтов в `allowedOrigins` и репозитории проекта в `repositories`.

```bash
npm start
```

Панель команды: [http://localhost:7337](http://localhost:7337). Она попросит приватный токен. Для примера из этого репозитория запустите в другом терминале `python3 -m http.server 7338 -d examples/site` и откройте [http://localhost:7338](http://localhost:7338). Значение `data-project-key` в `examples/site/index.html` должно совпадать с вашим `widgetKey`.

По умолчанию сервер принимает подключения только с этой машины (`host: "127.0.0.1"`). Для общего доступа разместите его за HTTPS-прокси; если прокси работает в другом контейнере или хосте, явно настройте `host` и ограничьте доступ сетевыми правилами.

Рекомендуемое развёртывание — отдельный экземпляр сервиса и база для каждого проекта в инфраструктуре этого проекта. Локальный, dev и production контуры одного проекта отправляют отчёты в этот общий экземпляр. Код и формат сервера остаются одинаковыми для всех проектов.

Пошаговый запуск с Docker Compose, HTTPS, резервным копированием и обновлением: [docs/DEPLOY.md](docs/DEPLOY.md). Это инструкция; текущий репозиторий сам ничего не развёртывает.

## Подключение к веб-проекту

После развертывания сервиса добавьте на страницу:

```html
<script src="https://bugs.example.com/widget.js" data-project-key="PUBLIC_WIDGET_KEY"></script>
```

На каждом проекте это делается один раз в общем шаблоне приложения. Кнопка появится у всех пользователей этой версии. Баги с разных контуров уходят в одну панель. Для локальной проверки добавьте локальный адрес приложения в `allowedOrigins`. Браузер тестировщика должен иметь доступ к серверу багов; локальный адрес самого тестировщика другим участникам доступен не будет, поэтому снимок и описание сохраняются на сервере.

Версию сборки можно передать через `data-app-version="..."` на этом же теге или через `<meta name="app-version" content="...">`. Она попадёт в карточку и HTML. Без версии отчёт всё равно создаётся.

Кнопка ищет свободное место рядом с правым нижним углом и перестраивается при прокрутке, масштабировании и изменении страницы. При ошибке автоматического снимка тестировщик может приложить изображение вручную.

Опциональный `data-capture-fetch-errors="true"` добавляет в карточку ошибки стандартного `fetch`: метод, путь без query-параметров, статус, время и, если сервер их вернул, `X-Request-Id`/`X-Error-Id`. Тела запросов и другие заголовки не сохраняются. Для собственного сетевого слоя используйте метод ниже.

Виджет автоматически запоминает ошибки JavaScript. Если приложение уже ведёт журнал запросов, передайте в карточку безопасный контекст ошибки:

```js
window.BugReportKit.instance.recordDiagnostic({
  eventType: 'CLIENT_REQUEST_ERROR',
  message: 'Не удалось сохранить форму',
  method: 'POST', path: '/api/forms', statusCode: 500,
  requestId: 'REQ-123',
});
```

Передавайте только путь без параметров, без заголовков и содержимого запроса. Последние 20 событий попадут в тикет. При ручном вызове `BugReportKit.init(...)` используйте `recordDiagnostic` на возвращённом объекте.

## API для агента

Приватный токен позволяет читать карточки и выполнять действия своей роли. HTML создаётся по текущим данным карточки; ZIP не требуется. Работа с кодом приложения остаётся задачей агента с отдельным навыком, а сервер хранит тикет и доказательства результата.

| Запрос | Назначение |
|---|---|
| `GET /api/projects` | Доступные проекты |
| `GET /api/me` | Имя и роль текущего токена |
| `GET /api/reports?project=ID&status=new&offset=0` | Список карточек, по 100 на страницу; фильтры применяются до разбиения |
| `GET /api/reports/ID` | Структурированные данные |
| `GET /api/reports/ID/screenshot` | Снимок |
| `GET /api/reports/ID/related` | Похожие баги в том же проекте |
| `GET /api/reports/ID/html` | Самодостаточный HTML-отчёт |
| `PATCH /api/reports/ID` | Действие `claim`, `ask`, `resolve`, `accept` и другие |
| `GET /api/summary?from=YYYY-MM-DD&to=YYYY-MM-DD` | Итоги за период |
| `GET /api/summary/html?from=YYYY-MM-DD&to=YYYY-MM-DD` | HTML-отчёт за период |

Для чтения и изменений передайте `Authorization: Bearer TEAM_TOKEN`. При `PATCH` передайте `revision` из последнего `GET` и `action`; устаревшая запись вернёт 409. Права токена ограничены проектами и ролью `developer`, `reviewer` или `admin`. Пример полного цикла и требования к доказательствам описаны в [контракте](docs/WORKFLOW.md).

Готовый [навык агента](skills/process-bug-report/SKILL.md) обрабатывает тикет по одному и оставляет окончательную приёмку человеку. Для запросов к API без ручной сборки заголовков есть `scripts/bug-kit-agent.mjs`.

## Ограничения первой версии

- Виджет предназначен для веб-страниц. Для мобильного или настольного приложения потребуется отдельный клиент.
- Скриншот строится через `html2canvas`; некоторые элементы страницы могут не попасть на изображение. В форме есть ручная загрузка снимка.
- Сервис сохраняет SQLite-базу в `data/`. Для командной работы сервер должен быть постоянно доступен и иметь резервное копирование.
- Адрес страницы сохраняется без query-параметров, чтобы случайно не записать токены из URL. Перед отправкой снимка тестировщик должен убедиться, что на нём нет личных данных.
- Это прототип: перед открытием сервиса в публичном интернете нужны HTTPS, управление учётными записями и проверка защиты от злоупотреблений. Текущие токены рассчитаны на ограниченную команду.
